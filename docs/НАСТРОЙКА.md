# Настройка

Всё живёт в `%APPDATA%\HIKA\config.json`. Файл создаётся при первом запуске
и **перечитывается на лету** — сохранил, и через полсекунды новое значение
уже работает. Перезапускать программу нужно только для смены модели
распознавания и звукового устройства.

Но открывать его руками почти никогда не нужно: всё то же самое есть в окне
настроек — щелчок по значку в трее. Там у каждой настройки написано обычными
словами, что она делает и чем оборачивается. Файл нужен для того, чего
в окне нет: своего каталога, аргументов командной строки у своих команд
и тонких настроек ранней проверки имени.

Чужие ключи в файле сохраняются: дописанное руками не стирается тем,
что окно записало поверх свой снимок.

Если файл испортить, программа не упадёт: она сохранит его рядом с пометкой
`.broken-<дата>` и поднимется со значениями по умолчанию. Числа при этом
проверяются на разумность: `probeAfterMs: 0` не превратится в проверку
имени на пустом звуке в бесконечном цикле, а подтянется к нижней границе.

---

## Прежде чем крутить ползунки

Настройки → **«Что происходит»**. Программа замеряет саму себя и показывает,
из чего сложилось ожидание: сколько ушло на паузу перед концом фразы,
сколько на распознавание, сколько на действие. Там же — что именно здесь
виновато и кнопка, которая это исправляет.

Это надёжнее любого угадывания по этому файлу. «Медленно» не диагноз:
полторы секунды могут быть полутора секундами распознавания, а могут —
четырьмя сотнями миллисекунд `audio.silenceMs` плюс тем же распознаванием,
и крутить в этих двух случаях надо разное.

## Слова пробуждения — `wake`

```json
"wake": {
  "words": ["хика", "ави"],
  "extraVariants": [],
  "tolerance": 0.34,
  "allowAnywhere": false
}
```

**`words`** — имена, на которые откликаться. Можно сколько угодно.
Варианты произношения для «хика» и «ави» уже прошиты внутри.

**`extraVariants`** — самое полезное поле во всём файле. Если распознаватель
стабильно слышит имя не так, впиши сюда то, что он выдаёт. Посмотреть можно
в журнале по строкам `услышано:` или в отчёте диагностики.

```json
"extraVariants": ["обои", "а ви", "авиа", "хико"]
```

Это надёжнее любой подстройки порогов: ты не расширяешь зону догадок,
а прямо называешь ещё одно правильное написание.

**`tolerance`** — сколько прощать расхождения, 0…0.6. Больше — срабатывает
чаще, но и ложно тоже. Разное для разной длины: трёхбуквенному «Ави» всегда
прощается ровно одна ошибка, сколько ни ставь.

- просыпается само во время разговора → уменьшить до `0.25`
- не слышит имя, хотя ты его говоришь → сначала `extraVariants`, и только
  потом поднимать до `0.42`

**`allowAnywhere`** — искать имя в любом месте фразы, а не только в начале.
По умолчанию выключено: включённое заметно повышает число ложных срабатываний.

## Распознавание речи — `speech`

```json
"speech": {
  "model": "small",
  "quantization": "q5_0",
  "language": "ru",
  "threads": 0,
  "modelDirectory": "",
  "earlyWakeProbe": true,
  "probeAfterMs": 600,
  "adaptiveContext": true,
  "fastDecoding": true
}
```

**`model`** — размер модели. Для русского это главный рычаг качества.

| Значение | Размер | Русский | Скорость на процессоре |
|---|---|---|---|
| `tiny` | 31 МБ | плохо | очень быстро |
| `base` | 57 МБ | слабо | быстро |
| `small` | 181 МБ | приемлемо | средне ← по умолчанию |
| `medium` | 539 МБ | хорошо | медленно |
| `largev3turbo` | 547 МБ | заметно лучше | медленно на процессоре, быстро на видеокарте |

`largev3turbo` при том же весе, что `medium`, распознаёт русский ощутимо
лучше — если готов ждать, бери его. С видеокартой (см. ниже) он же становится
и самым быстрым вариантом.

**`quantization`** — `q5_0`, `q8_0` или `none`. Квантованные модели меньше
и быстрее почти без потери качества. Менять смысла нет.

**`language`** — `ru`, `en` или `auto`.

По умолчанию `ru`, и это осознанно. Автоопределение языка на фразе длиной
в секунду («Ави, ютуб») ненадёжно и уводит модель не туда. В русском режиме
английские названия приезжают кириллицей — «опен ворд» — но распознаватель
команд переводит их обратно через транслитерацию, так что английские команды
продолжают работать.

Ставь `auto`, только если говоришь по-английски не реже, чем по-русски.

**`threads`** — потоков распознавания. `0` = все ядра, кроме пары
оставленных системе, но не больше восьми. Выше прирост всё равно
заканчивается.

**`earlyWakeProbe`** — та самая ранняя проверка, из-за которой кайма
загорается посреди фразы, а не после неё. Стоит одного дополнительного
короткого распознавания на каждое произнесённое рядом слово. Если процессор
слабый и это заметно — выключи, но реакция станет запаздывающей.

**`probeAfterMs`** — через сколько миллисекунд речи делать раннюю проверку.
Меньше — быстрее зажигается, но чаще мимо (имя может ещё не прозвучать).

**`adaptiveContext`** — считать окном по длине фразы. Здесь лежит самый
большой запас по отзывчивости во всей программе, и стоит объяснить, откуда
он берётся.

Whisper всегда работает окном в тридцать секунд. Сколько бы человек
ни сказал — «Ави, открой стим» длится две секунды, — модель дополняет запись
тишиной до тридцати и прогоняет через кодировщик всё окно. Двадцать восемь
секунд из тридцати уходят на обработку тишины, которую мы сами же и дописали.

Тридцать секунд дают полторы тысячи позиций кодировщика — пятьдесят
на секунду. Для двухсекундной команды хватает ста с небольшим, и работы
остаётся в разы меньше.

Расплата: модель не обучалась на обрезанном окне, и при слишком жёсткой
обрезке качество падает. Поэтому запас щедрый, а размер округляется
до нескольких ступеней. Если три распознавания подряд вернут пустоту,
программа сама вернётся к полному окну и напишет об этом в журнал.

**`fastDecoding`** — не переспрашивать себя. Не сойдясь с порогами
уверенности, whisper по умолчанию перезапускает расшифровку с другой
температурой, и так до пяти раз. Для расшифровки лекции это правильно,
для команды из трёх слов означает пятикратное ожидание там, где человек
уже понял, что его не услышали, и повторил.

## Звук — `audio`

```json
"audio": {
  "device": "",
  "gain": 1.0,
  "vadThreshold": 0.5,
  "silenceMs": 400,
  "minSpeechMs": 260,
  "maxUtteranceMs": 15000,
  "preRollMs": 320,
  "energyThreshold": 0.012
}
```

**`device`** — часть имени микрофона, регистр неважен. Пусто — устройство
по умолчанию. Список: `Hika.exe --list-audio`

```json
"device": "Blue Yeti"
```

**`gain`** — программное усиление. Если в диагностике пиковый уровень ниже
`0.01`, ставь `2.0`–`3.0`.

**`vadThreshold`** — насколько уверенно нужно определить речь, 0…1.

- реагирует на клавиатуру, музыку, шум → поднять до `0.6`–`0.7`
- не замечает тихую речь → опустить до `0.35`

**`silenceMs`** — сколько тишины считать концом фразы. Это чистая задержка
перед каждой командой: раньше этого срока распознавание даже не начнётся,
сколько бы его ни ускоряли.

Ошибиться здесь дёшево в обе стороны. Слишком мало — фраза разрежется
на паузе, и остаток придёт следующей репликой, которую всё равно примут
как продолжение. Слишком много — человек ждёт каждый раз.

**`minSpeechMs`** — короче этого считается шумом. Защита от кашля, щелчков
и хлопнувшей двери.

**`preRollMs`** — сколько звука *до* начала речи подмешивать в запись.
Детектор неизбежно опаздывает на пару кадров, и без этого буфера срезается
начало первого слова — то есть ровно то место, где звучит имя. Уменьшать
не стоит.

## Свечение — `overlay`

```json
"overlay": {
  "enabled": true,
  "monitors": "primary",
  "thickness": 0.07,
  "maxOpacity": 0.55,
  "showBeforeWakeWord": false,
  "sensingOpacity": 0.18,
  "voiceReactivity": 0.75,
  "colors": ["#3AA0FF", "#8A6CFF", "#FF5FA2", "#31D6BC"],
  "successColor": "#3BE07E",
  "errorColor": "#FF5A4E",
  "targetFps": 60,
  "excludeFromCapture": false
}
```

**`monitors`** — `primary` или `all`.

**`thickness`** — толщина каймы в долях меньшей стороны экрана.
`0.07` ≈ 75 px на 1080p, ≈ 151 px на 4K. Диапазон разумного: `0.04`–`0.12`.

Свет занимает не всю эту полосу, а её внешнюю треть — остальное уходит
в мягкое затухание, чтобы граница света не была заметна. Поэтому число
выглядит больше, чем видно на экране.

**`maxOpacity`** — предел яркости. Весь смысл настройки в том, чтобы кайма
обозначала себя и не засвечивала экран. `0.3` — совсем деликатно,
`0.7` — уже назойливо.

**`showBeforeWakeWord`** — светиться ли, ещё не зная, к нам ли обращаются.
Выключено, и это важнее, чем кажется. Задумывалось как вежливость: человек
видит, что его услышали, ещё до того, как имя распозналось. На деле кайма
вспыхивала от любого звука в комнате — от разговора рядом, от видео,
от кашля, — и вместо «я тебя слушаю» читалась как «программа мигает сама
по себе». Свечение обязано означать ровно одно: прозвучало имя. Иначе оно
перестаёт что-либо значить.

**`sensingOpacity`** — яркость этого слабого свечения. Действует, только
если включено `showBeforeWakeWord`. Должна быть заметно ниже `maxOpacity`:
если обращались не к ассистенту, человек не должен отвлекаться.

**`voiceReactivity`** — насколько сильно голос раскачивает свечение, 0…1.
`0` — ровное дыхание без реакции на речь, `1` — только голос.

**`colors`** — четыре цвета углов: верхний левый, верхний правый, нижний
правый, нижний левый. Между ними идёт непрерывный переход по периметру.
Одинаковые четыре цвета дают ровную одноцветную кайму.

**`targetFps`** — кадров в секунду. `30` экономит батарею ноутбука, разница
на глаз почти незаметна.

**`excludeFromCapture`** — прятать свечение от записи экрана и скриншотов.
Удобно, если стримишь или снимаешь обучающие видео.

## Поведение — `behavior`

```json
"behavior": {
  "armedSeconds": 6,
  "webSearchFallback": true,
  "searchUrl": "https://www.google.com/search?q={q}",
  "matchThreshold": 0.62,
  "indexInstalledApps": true,
  "reindexMinutes": 30,
  "logTranscripts": true,
  "autostart": false,
  "startMuted": false,
  "listenHotkey": "Ctrl+Alt+Space",
  "muteHotkey": "Ctrl+Alt+H",
  "logLevel": "info"
}
```

**`armedSeconds`** — сколько ждать команду после голого «Ави». `0` отключает
режим ожидания: имя и команда должны быть в одной фразе.

**`listenHotkey`** — клавиша «слушай». Одно нажатие — команду можно говорить
без имени; выполнила и снова спит. Окно продолжения после такой команды
не открывается: нажатие означает одну просьбу целиком. Второе нажатие, пока
она слушает, — отбой.

Нужно чаще, чем кажется: имя приходится произносить вслух, а вслух удобно
не везде — рядом спят, идёт запись, в наушниках созвон.

**`muteHotkey`** — клавиша выключения микрофона, то же, что пункт в меню значка.

Обе записываются одинаково: модификаторы через `+`, потом клавиша —
`Ctrl+Alt+Space`, `Shift+F5`, `Ctrl+Alt+H`. Пусто — не назначать. Проще
задавать в окне настроек, «Поведение» → «Горячие клавиши»: там достаточно
нажать то сочетание, которое хочешь.

Клавиша без модификатора не принимается — назначить глобально одну «H»
значит, что эта буква перестанет набираться во всей системе. Исключение —
F1…F24 и Pause, которые сами по себе ничего не печатают.

Если сочетание уже занято другой программой, Windows его не отдаст. Молча
это не проходит: появится всплывающее сообщение с предложением выбрать другое.

**`webSearchFallback`** — если команда ни на что не похожа, искать её
в интернете. Молча проглотить команду хуже, чем показать результаты поиска:
человек хотя бы увидит, что его услышали.

**`matchThreshold`** — насколько уверенным должно быть совпадение, чтобы
что-то запустить, 0.3…0.95.

- запускает не то → поднять до `0.72`
- не находит очевидное → опустить до `0.55`

Посмотреть, как оценивается конкретная фраза, можно в диагностике: она
печатает три лучших варианта с оценками.

**`logTranscripts`** — писать распознанный текст в журнал. Это твоя речь,
оседающая на диске. Незаменимо при настройке распознавания и совершенно
не нужно потом — выключи, когда всё заработает.

**`logLevel`** — `trace`, `debug`, `info`, `warn`, `error`. При разборе
проблем ставь `debug`: появятся строки о том, как оценивался каждый кандидат.

## Свои команды — `custom`

```json
"custom": [
  {
    "phrases": ["работа", "рабочая почта"],
    "target": "https://mail.company.ru/"
  },
  {
    "phrases": ["мой проект"],
    "target": "C:\\Users\\Я\\Projects\\hika\\HIKA.sln"
  },
  {
    "phrases": ["музыка", "включи музыку"],
    "target": "spotify"
  }
]
```

`target` — ссылка, путь к файлу, имя программы или идентификатор приложения
Windows. Есть ещё поле `arguments`, если программу нужно запустить с ключами.

Свои команды весят больше встроенных: при одинаковой похожести выиграют они.

Если записей много, вынеси их в `%APPDATA%\HIKA\catalog.json` — формат тот же,
что у встроенного `catalog.default.json` рядом с программой.

## Ускорение на видеокарте

Распознавание уедет с процессора на видеокарту. С `largev3turbo` разница
принципиальная: секунды превращаются в доли секунды.

**NVIDIA** — нужен установленный CUDA 12 Runtime:

```
dotnet publish src/Hika.App/Hika.App.csproj -c Release -o build -p:HikaCuda=true
```

**AMD, Intel и вообще всё остальное** — через Vulkan:

```
dotnet publish src/Hika.App/Hika.App.csproj -c Release -o build -p:HikaVulkan=true
```

## Где что лежит

```
%APPDATA%\HIKA\
├── config.json          настройки
├── catalog.json         свои команды (если создашь)
├── models\              модели распознавания
│   ├── silero_vad.onnx
│   └── ggml-small-q5_1.bin
├── logs\                журнал, хранится неделю
└── диагностика-*.txt    отчёты проверки
```

Рядом с `Hika.exe` лежит только `Catalog\catalog.default.json` — встроенный
каталог. Править его не нужно, он перезаписывается при обновлении.
